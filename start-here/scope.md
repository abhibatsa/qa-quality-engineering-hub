# What This Repo Covers (and What It Doesn't)

**Read this first** — it saves you time later, and it saves this repo
from becoming an unfocused catch-all.

## What's in scope

Everything a QA, QE, or Quality Manager actually does across a real
career: process (test planning, estimation, defect management),
technical practice (frameworks, automation, DB/DSA fundamentals), and
AI-QA (testing non-deterministic systems, using AI to speed up testing
itself). If it's something a Quality Engineer is responsible for or
graded on, it belongs here.

## What's explicitly out of scope, and where it actually lives

| Topic | Why it's out | Where it lives instead |
|---|---|---|
| SRE, SLOs, incident response, on-call | Reliability engineering is its own discipline with its own career track, not a QA sub-skill | [Observability & Monitoring](https://github.com/abhibatsa/architecting-software) |
| Deep language-specific automation code (Selenium/Playwright/Karate syntax) | Already has a dedicated, deeper home | [SDET / Automation Career Prep](https://github.com/abhibatsa/sdet-automation-career-prep) |
| Interview prep / career-ladder framing | This repo is a reference, not a career-prep track | [SDET / Automation Career Prep](https://github.com/abhibatsa/sdet-automation-career-prep), [AI Test Engineering Career Prep](https://github.com/abhibatsa/ai-test-engineering-career-prep) |
| System/architecture design patterns | Belongs with architecture content, not QA process | [System Design & Architecture](https://github.com/abhibatsa/architecting-software), [LLD & OOD Interview Prep](https://github.com/abhibatsa/lld-and-ood-interview-prep) |

## Why the split matters

A repo that tries to be everything to everyone ends up thin everywhere.
Keeping SRE, deep automation syntax, and interview-prep framing in their
own dedicated repos means this one can go deep on what's actually
distinct to QA/QE — process discipline, quality judgment, and
increasingly, testing systems that don't behave deterministically —
without duplicating content that's already done well elsewhere.

## How to use this repo

Not meant to be read front-to-back. Use the category index in the root
[`README.md`](../README.md) to jump to what you need, when you need it —
prepping a test plan, setting up a reporting pipeline, or figuring out
how to test an LLM-based feature for the first time.
